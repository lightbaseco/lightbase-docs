Indexer reconstructs each schema from the accesses it observes in the code. Under some circumstances it is not possible to reconstruct every detail precisely, for example when a column is never read by any query, when the hostname only appears as an environment variable, or when logic runs inside the database, in a trigger or a stored procedure.

In **Databases and tables** you fill in those gaps. You can declare databases, mark replicas, and review the tables discovered during [indexing](/indexing/indexer), merging duplicates and editing schemas.

## Manage your databases

Define the databases that matter and describe them in the terms your team uses.

* **Name, alias, and engine.** The logical name your services use, alongside the real one.
* **Host and description.** Enough context that anyone following the data lineage knows which system it is.
* **Replication.** Mark a database as a replica of another, so reads against the replica trace back to the same data as the primary.

## Edit schemas

A curated table is editable at field level.

* Column **names and types**, plus **primary key** and **nullable** flags.
* **Foreign keys** pointing at other tables.
* A **category** per column, and as many **categories** as you need per table. Categories are free-text tags such as `sensitive` or `financial`. They follow the data through every flow that reads it.
* The **column mapping** per service, so a rename in one place keeps the link to the rest.

## Upload a DDL

You can generate a DDL file with a schema dump of your database. Once you upload it, the definition becomes authoritative and Indexer keeps it updated if it finds evidence of changes to it.

The model then holds every column with its real type, including those no query touches, and the constraints the database enforces.

The DDL also settles the naming. Applications refer to the same column in different ways, and matching the names used in the code against the ones the database declares keeps those references pointing at a single column.

<Tip>
  A DDL is the fastest way to curate a large, mature schema. Lightbase fills in the structure so you only curate naming and business meaning.
</Tip>
