An **application** is a deployable unit from your codebase: a backend service, a frontend web app, or a set of scripts. These are the services Indexer identifies in each repository.

[Detection](/indexing/indexer) names each application after its repository or manifest, which is often not the name your team uses. In curation you can rename them and group them by team, domain, stack or any custom grouping you require.

## Application groups

Group applications into the units you work with: a product, a domain, a platform, a team's surface area. Explorations can then be scoped to a group.

## Environment variables

Hostnames, connection strings and similar values are injected into an application through environment variables, and might not be available in the code. Supplying those values here lets Indexer resolve a `DATABASE_URL` to a [database](/data-curation/databases), or a service address to the application that serves it.

## Enable and disable

Disable an application to take it out of the model without changing what you index. Use it for a deprecated application, a folder of generated code, or a false positive from application detection.
