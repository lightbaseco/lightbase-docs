Lightbase connects to your source control, indexes the repositories you choose, and builds a model of how your system works. This page walks you through connecting a provider, letting Lightbase build that model, and querying it from your AI client.

## Before you start

You need:

- Admin access in your Lightbase organization
- Permission to authorize or install integrations in your source control provider
- Access to the repositories, group, or workspace you want Lightbase to use

## Set up Lightbase

<Steps>
    <Step title="Connect your source control provider">
        Connect Lightbase to GitHub, GitLab, or Bitbucket. This authorizes Lightbase to read the repositories you choose. Connecting a provider requires admin access in your Lightbase organization.
        <Tabs>
            <Tab title="GitHub">
                To connect GitHub, start the GitHub connection flow in Lightbase and authorize the integration in GitHub. You can choose which organization to install the GitHub app in.

                <Note>
                  Depending on how the GitHub organization is managed, an owner or admin may need to approve the installation before it becomes active. If that's not you, your request is sent to an owner for approval.
                </Note>

                Once the connection is approved, GitHub shows the repositories Lightbase will have access to. You can select all of them or choose a subset.

                After the installation, the Lightbase GitHub App appears under the **GitHub Apps** section in your GitHub organization settings.
            </Tab>
            <Tab title="GitLab">
                  To connect GitLab, authorize the integration in GitLab and then choose the top-level GitLab group you want Lightbase to use. Lightbase uses that group to discover the repositories available for selection, skipping any repository that is not in the group.

                  The integration is linked to the personal account that authorizes it, not to the group selected. You can review or revoke it under **Authorized applications** in your GitLab account settings.

                  <Tip>
                      Create a dedicated account for the integration instead of using your personal one, so more people can access it if necessary.
                  </Tip>
            </Tab>
            <Tab title="Bitbucket">
                  To connect Bitbucket, authorize the integration in Bitbucket and then choose the Bitbucket workspace you want Lightbase to use. Lightbase uses that workspace to discover the repositories available for selection, skipping any repository that is not in the workspace.

                  The integration is linked to the personal account that authorizes it, not to the workspace or organization selected.

                  <Tip>
                      Create a dedicated account for the integration instead of using your personal one, so more people can access it if necessary.
                  </Tip>
            </Tab>
        </Tabs>
    </Step>
    <Step title="Select the repositories to index">
        During setup, you choose which repositories Lightbase indexes. The rest stay disabled and are excluded from analysis. You can change this selection at any time, see [Repository management](/getting-started/repositories).
    </Step>
    <Step title="Lightbase builds your model">
        Lightbase indexes the selected repositories automatically to build the first version of your organization's model. You don't need to trigger anything. See [the indexing process](/indexing/indexer) for what happens during the initial index.
    </Step>
    <Step title="Connect the MCP server">
        Give your AI client access to your model through the Lightbase MCP server. Point your client at:

        ```
        https://mcp.lightbase.co
        ```

        <Info>
            You don't generate or pass a token. The server authenticates each call directly, and your first connection opens a browser window to sign in with your Lightbase account.
        </Info>

        Add the endpoint to your client's configuration. The exact format depends on the client:

        <Tabs>
            <Tab title="VS Code">
                Add the server to `.vscode/mcp.json`:

                ```json .vscode/mcp.json
                {
                    "servers": {
                        "lightbase": {
                            "url": "https://mcp.lightbase.co"
                        }
                    }
                }
                ```
            </Tab>
            <Tab title="Cursor">
                Add the server to `.cursor/mcp.json`:

                ```json .cursor/mcp.json
                {
                    "mcpServers": {
                        "lightbase": {
                            "url": "https://mcp.lightbase.co"
                        }
                    }
                }
                ```
            </Tab>
            <Tab title="IntelliJ">
                Go to **Settings | Tools | AI Assistant | Model Context Protocol (MCP)**, click **Add**, and paste:

                ```json
                {
                    "mcpServers": {
                        "lightbase": {
                            "url": "https://mcp.lightbase.co"
                        }
                    }
                }
                ```
            </Tab>
            <Tab title="Claude Code">
                ```bash
                claude mcp add --transport http lightbase https://mcp.lightbase.co
                ```
            </Tab>
            <Tab title="Codex">
                Add the server to `~/.codex/config.toml`:

                ```toml ~/.codex/config.toml
                [mcp_servers.lightbase]
                url = "https://mcp.lightbase.co"
                ```
            </Tab>
        </Tabs>

        Any other MCP-compatible editor or agent uses the same server URL. Check its own MCP documentation for the exact configuration format.
    </Step>
</Steps>
