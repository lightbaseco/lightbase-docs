Lightbase indexes every repository in your organization and builds one model of your entire system. This model holds every relationship between your services, [databases](/data-curation/databases), [business entities](/data-curation/business-entities), and [counterparties](/data-curation/counterparties), knowledge that is often fragmented among teams and people.

Your agent works only with the context of the repository it's working on. The Lightbase MCP gives your agent access to that model providing it answers every aspect of your full codebase and business.  

How this supercharges your agent:

- Give it full visibility of every code flow affected by a change, across every service. This helps agents understand the hidden contract behind a given piece of code and prevents them from breaking downstream consumers or introducing bugs that are difficult to catch.
- Help it understand the lineage of data: what a given field in the database means, how the content of a report in S3 is calculated, who are the writers and consumers. Because they now have the meaning and intent of the data, they require less input from the user and write code that won't introduce silent data corruption.
- Improve its ability to diagnose errors. Your agent can ask Lightbase to explain the root cause and suggest possible fixes. This is particularly useful when the cause lies outside the current repository or the code alone does not explain the failure. Examples include a breaking change in an upstream service or incorrect data written by another code flow.

<Info>
  If you [connect your infrastructure](/indexing/infrastructure) to Lightbase, the MCP server gives your agent visibility of your cloud resources.
</Info>

## Before you start

You need:

- A Lightbase account with at least one repository connected and indexed.
- Remote MCP server using stateless Streamable HTTP with OAuth authentication.

## Connect to the MCP server

Every MCP client connects to the same Lightbase endpoint:

```
https://mcp.lightbase.co
```

Add the endpoint to your client's configuration. The exact format depends on the client:

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http lightbase https://mcp.lightbase.co
    ```
  </Tab>
  <Tab title="Codex">
    Add the server to `~/.codex/config.toml`:

    ```toml ~/.codex/config.toml
    [mcp_servers.lightbase]
    url = "https://mcp.lightbase.co"
    ```
  </Tab>
  <Tab title="Cursor">
    Add the server to `.cursor/mcp.json`:

    ```json .cursor/mcp.json
    {
      "mcpServers": {
        "lightbase": {
          "url": "https://mcp.lightbase.co"
        }
      }
    }
    ```
  </Tab>
  <Tab title="VS Code">
    Add the server to `.vscode/mcp.json`:

    ```json .vscode/mcp.json
    {
      "servers": {
        "lightbase": {
          "url": "https://mcp.lightbase.co"
        }
      }
    }
    ```
  </Tab>
  <Tab title="Jetbrains IDEs">
    Go to **Settings | Tools | AI Assistant | Model Context Protocol (MCP)**, click **Add**, and paste:

    ```json
    {
      "mcpServers": {
        "lightbase": {
          "url": "https://mcp.lightbase.co"
        }
      }
    }
    ```
  </Tab>
</Tabs>

Any other MCP-compatible editor or agent uses the same server URL. Check its own MCP documentation for the exact configuration format.

### Multiple organizations

Your client works with one organization at a time. If you belong to more than one Lightbase organization, add the `org` parameter to the server URL:

```
https://mcp.lightbase.co?org=acme
```

Set it to the organization's slug, the short identifier chosen when it was created. Without the parameter, Lightbase answers from your default organization.

## Authentication

The MCP server uses OAuth 2.1. Each MCP client registers through Dynamic Client Registration, which lets it enroll with the authorization server without manual setup.

The first time the client connects, it opens a browser window. Sign in with the account you already use for Lightbase.

You do not need to generate or add an API key to the client configuration. The OAuth flow manages authentication without storing a long-lived secret there. Lightbase attributes each request to the person who signed in and removes access when they leave the organization.

## Available tools

Lightbase currently exposes a single tool, `query`, which gives your agent all the context described above.

### Query
